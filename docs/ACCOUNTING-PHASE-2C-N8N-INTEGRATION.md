أُضيف أساس فعلي ومحلي لوظائف أتمتة الشركة، واستقبال نتائج كشف البنك بعقد صارم وتوقيع HMAC، وتخزين الحركات بدقة عشرية، ومراجعتها وتصحيحها مع سجل قرارات. توجد واجهتان عربيتان داخل مساحة الشركة: مركز الأتمتة ومراجعة كشوف الحساب. العينة المحلية اصطناعية بالكامل، ولا تُرفع PDF ولا تتصل بـ n8n. الربط الحي محجوب في الكود، حتى لو توفرت إعدادات الاتصال، لأن فحص الملفات والحجر والتنفيذ المجدول غير مكتملين.

لم تُنشر التغييرات. شجرة العمل بدأت وبقيت تحتوي تعديلات وملفات غير متتبعة من Phase 2A و2B وأعمال سابقة؛ ترحيلات Phase 2A/2B/2C غير موجودة في commit الأساس `9d3259a`، ولم يُؤذن بتطبيقها على الإنتاج. نشرها الآن قد يكسر التطبيق أو يفعّل مسار مستندات غير آمن.

  U[مستخدم مصرح داخل الشركة] --> A[مركز الأتمتة]

حالات الوظيفة: `CREATED`, `QUEUED`, `PROCESSING`, `NEEDS_REVIEW`, `REVIEWED`, `REVIEW_REJECTED`, `PROCESSING_FAILED`, `TIMED_OUT`, `CANCELLED`. المسار العامل الآن محليًا هو إنشاء عينة صريحة ← معالجة العينة ← نتيجة محفوظة تنتظر مراجعة ← مراجعة بشرية تؤدي إلى `REVIEWED` أو `REVIEW_REJECTED`. إعادة محاولة العينة متاحة للفشل أو المهلة/المعالجة المتقادمة، بحد ثلاث محاولات ونسخة متفائلة. حالات معالجة الملفات الفعلية وdispatch الحي محفوظة كحدود تصميمية وليست مفعلة.

## 5. عقد n8n والـ Callback

العقد `moneycoder.bank-statement.v1` في `src/lib/accounting/bank-contract.ts` يحد النتيجة إلى 1000 حركة وحقول صريحة: هوية الوظيفة، العملة، البنك، الفترة، الأرصدة والإجماليات، حالة الحساب، التحذيرات، إصدار المحلل، ومعرّف/تاريخ/مرجع/وصف/مدين/دائن/رصيد جارٍ لكل حركة. الأرقام الصحيحة الآمنة أو السلاسل العشرية مقبولة؛ تُرفض الكسور غير الدقيقة، القيم السالبة غير الجائزة، حركة مدين ودائن معًا، التكرار، والخطأ في العدد أو الفترة. يُعاد احتساب جميع الإجماليات والأرصدة، ولا تُقبل نتيجة n8n كسلطة محاسبية.

`POST /api/internal/automation/results` يحد جسم الطلب إلى 512,000 بايت أثناء القراءة نفسها. التوقيع `HMAC-SHA256(secret, timestamp + "." + nonce + "." + rawBody)` في رؤوس `x-mc-timestamp`, `x-mc-nonce`, `x-mc-signature`. يُقبل زمن لا يتجاوز خمس دقائق، وتستخدم مقارنة ثابتة الزمن، ويُحفظ nonce مرة واحدة. تُستنتج الشركة والحساب من الوظيفة المنشأة في الخادم؛ لا يُوثق معرف شركة مرسل من callback. قفل صف الوظيفة ومعاملة `Serializable` وبصمة النتيجة يمنعان الإدخال المكرر والنتائج المتعارضة. ردود API لا تعيد السر أو رؤوس الطلب.

**لا يوجد dispatch من Vercel إلى n8n الآن.** `AUTOMATION_MODE=REMOTE` يظل غير متاح حتى مع إعدادات اتصال تبدو صحيحة. لا يوجد إثبات أن MC-04 يرسل callbacks بهذا العقد؛ يحتاج تعديلًا واختبارًا منفصلين خارج هذا المستودع.

## 7. تجربة المراجعة والتصدير

مركز الأتمتة يعرض الأعداد الفعلية المخزنة، التحديث الأخير، البحث والحالة والفترة والترقيم، رسائل الفشل، والانتقال إلى الكشف. وضع `DISABLED` يعرض عدم التوفر بوضوح؛ وضع `MOCK` متاح محليًا فقط وبعينة اصطناعية معلنة.

صفحة الكشف تعرض الشركة وحسابها والبنك المستخرج، الفترة والعملة والأرصدة والمطابقة الحسابية، الحركات الأصلية والمصححة، البحث والمرشحات وقرارات المراجعة. سطح المكتب جدول، والمحمول بطاقات. لا يوجد معاينة مستند أصلي موهومة. التصحيح يحتفظ بالقيمة الأصلية وسبب التغيير والفاعل، ولا يمكن إقرار الكشف إلا بعد مراجعة كل الحركات ومطابقة الأرصدة حتى بعد أي تصحيح. التصدير XLSX يستخدم ExcelJS، يمنع حقن الصيغ في النصوص، ويضع وصفًا صريحًا بأنه **ليس قيدًا محاسبيًا أو تسوية مع الدفاتر**. يُسجل حدث تصدير.

رفض كشف البنك لا يساوي فشل استخراجه. يسجل النظام `REVIEW_REJECTED` للوظيفة و`REJECTED` للكشف داخل معاملة واحدة، مع قرار تدقيق منفصل.
