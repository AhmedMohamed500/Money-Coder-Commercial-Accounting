## A. الملخص التنفيذي

استُبدلت صفحة Executive V8 العامة بتجربة V9 عربية تفاعلية تعرض مسار «من المستند إلى القرار». تُظهر الصفحة أساس المنتج المتاح حاليًا، ثم تسمح للزائر باستكشاف نماذج مالية افتراضية منفصلة بوضوح. الواجهة لا تعالج مستندات الزوار، ولا تتصل بحساباتهم البنكية، ولا تُنشئ قيودًا أو سجلات حقيقية.

تتضمن V9 مقدمة متحركة قابلة للتحكم، اختيار دور ونشاط يغيّر سياق العرض، مساحة عمل متعددة الواجهات، رحلة حركة مالية، تجربة كشف Horizon الافتراضي، مركز موبايل، ومحاكاة قرار مالي بمعادلة منشورة. توجد لقطات فعلية من متصفح على المقاسات المطلوبة ونتائج اختبارات آلية.

## B. مشاكل V8 التي عالجها الإصدار

1. كانت المقدمة وأقسام العرض كبيرة المسافات؛ ظهرت مساحة عمل V8 منخفضة في الشاشة عند بعض المقاسات.
2. كانت الواجهات التوضيحية ثابتة نسبيًا، وتبديل التبويبات لا يعطي رحلة مالية متكاملة.
3. تكرر نمط العناوين والوصف والنوافذ عبر الصفحة، وقلّ التركيز على ما يحتاج قرار المستخدم.
4. اعتمدت الحركة أساسًا على ظهور العناصر وتبديل الحالات القصير.
5. ظهر في نشر V8 تعارض اسم `.hero-grid` مع الأنماط العامة وأخفى الـHero؛ عُولج ذلك سابقًا، ثم استُخدمت في V9 أسماء فئات فريدة تبدأ بـ`mc9-` مع اختبار CSS الإنتاجي الفعلي.

## G. التحقق المحاسبي

- **كشف Horizon الافتراضي:** 15 حركة؛ رصيد افتتاحي 42,500، وارد 56,700، منصرف 33,010، رصيد ختامي **66,190 ج.م**. المعادلة: `42,500 + 56,700 − 33,010 = 66,190`.
- **تحصيل ذمة عميل 15,000 ج.م، المرجع `HTB-260201`:** مدين البنك 15,000، دائن العملاء 15,000. هذا تحصيل ذمة قائمة، ولا يعني إيرادًا جديدًا. فاتورة العميل ومطابقة الذمة ما زالتا تحتاجان مراجعة بشرية.
- **سداد مورد 5,500 ج.م:** مدين الموردون، دائن البنك، بافتراض تسوية التزام قائم. **إيجار 2,300 ج.م:** مدين مصروف الإيجار، دائن البنك، بافتراض تخصيصه للفترة. كل القيود تعليمية ومتوازنة ولم تُرحّل.
- **Decision Lab:** `النقدية المتوقعة = نقدية البداية + التحصيلات − التحصيلات المتأخرة − المدفوعات − المصروفات الإضافية`. الأساس: `50,000 + 30,000 − 0 − 20,000 − 0 = 60,000`. لا تسمح الواجهة بأن تتجاوز التحصيلات المتأخرة إجمالي التحصيلات.
- **مثال المصنع:** مواد 120,000 + أجور 60,000 + تكاليف صناعية غير مباشرة 40,000 = تكلفة إنتاج 220,000. بافتراض بيع كل الإنتاج: مجمل الربح 80,000 من مبيعات 300,000؛ وبعد مصاريف تشغيل 30,000 يصبح الربح التشغيلي 50,000. إذا بقي مخزون، فلا تساوي تكلفة الإنتاج تكلفة البضاعة المباعة تلقائيًا.

## H. الموبايل والتجاوب

فُحصت عروض 1920، 1693، 1440، 1280، 1024، 768، 430، 390، و360px. النتيجة: **صفر تمرير أفقي**، وصفر صور مكسورة، ولا قسم Hero بارتفاع صفر. على الشاشات الصغيرة تتحول الواجهة إلى تنقل أفقي داخل مركز التحكم، وتظهر حركات البنك كقائمة واضحة بدل جدول مصغر، ويصبح الـHero بمشهد واجهة واحد مقروء. الهاتف المعروض في Pocket CFO يظل ثابتًا بينما يتغير محتواه.

## I. الوصولية وRTL

- العربية هي الاتجاه الأساسي، مع `ltr` للأرقام والمراجع الإنجليزية.
- كل أزرار التبديل والتنقل لها حالات `aria-pressed` أو `aria-current` عند الحاجة؛ التحديثات الرئيسية تستخدم `aria-live`.
- فُحص التنقل بلوحة المفاتيح داخل مركز التحكم واختيار حركة كشف البنك. قائمة الموبايل تُغلق بعد اختيار الرابط.
- توجد حالة تركيز مرئية، وعناصر التحكم قابلة للمس ولوحة المفاتيح.
- تدعم CSS إعداد `prefers-reduced-motion`، مع تجربة ثابتة مفهومة دون انتظار اكتمال JavaScript.

## J. الأداء وحدود القياس

استخدمت التجارب `useState` وCSS ومتصفح الويب، دون إضافة مكتبات حركة أو تغيير تبعيات المشروع. بنت معاينة Next معزولة بنجاح باستخدام Webpack. في فحص المتصفح المحلي، لم تُرصد طلبات إلى نطاقات خارجية من أدوات العرض. لم يُشغّل Lighthouse ولم يُنشر رقم أداء غير مقاس. لقطات المتصفح تعكس بيئة اختبار محلية ولا تمثل قياس زمن تحميل على شبكات المستخدمين.

أُجري الفحص للواجهة العامة فقط؛ لا يمثل اختبارًا للمصادقة الفعلية أو قواعد البيانات أو رفع المستندات. لا توجد نتيجة Lighthouse أو قياس أداء رسمي في هذه المهمة.

## P. الأمان والبنية التحتية

لم تُشغّل migrations، ولم تُعدّل Neon أو قواعد بيانات أو بيانات مستخدمين، ولم يُوصل n8n بالموقع. لم تُقرأ أو تُنسخ ملفات أسرار. لم تُعدّل المصادقة أو API أو Prisma أو التخزين أو أعمال Phase 1.7/1.8 الأمنية. بُنيت المعاينة في مجلد معزول يحتوي على ملفات واجهة وأصول عامة فقط، ثم حُذف بعد التحقق. بقيت التعديلات المحلية السابقة خارج commit V9.

## Q. ما يلزم قبل تحويل العرض إلى خدمة محاسبية حقيقية

يتطلب الربط الإنتاجي المستقبلي API خادميًا آمنًا، تفويضًا وعزلًا لكل شركة، فحص الملفات ومكافحة البرمجيات الضارة، ضبط التكرار، سجلات تدقيق، مراجعة واعتمادًا بشريين، واختبارات تكامل محاسبي وقاعدة بيانات. لم يبدأ هذا العمل ضمن V9 التسويقي.

## R. الخلاصة

نُفذت V9 واختُبرت محليًا في بناء معزول، ونُشر كودها على GitHub ونجح نشر Vercel. اجتاز الموقع الحي فحص العرض والتفاعل الأساسي على سطح المكتب والموبايل. تبقى التجارب المالية التعليمية منفصلة عن الوظائف المحاسبية الحقيقية، وتبقى الاختبارات المتخطاة والربط الإنتاجي المستقبلي كما هو موضح أعلاه.
