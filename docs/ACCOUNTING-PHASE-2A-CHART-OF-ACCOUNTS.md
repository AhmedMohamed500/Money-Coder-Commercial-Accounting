# Money Coder — تقرير Phase 2A: دليل الحسابات التجاري

**التاريخ:** 31 أكتوبر 2026 — توقيت القاهرة
**الحالة:** منفذ ومختبر محليًا؛ يحتاج مراجعة محاسبية وأمنية واعتماد ترحيل قاعدة الإنتاج قبل النشر.
**الموقع المنشور حاليًا:** https://money-coder-commercial-accounting.vercel.app/ — لا يحتوي Phase 2A حتى تاريخ هذا التقرير.

## 1. خط الأساس الفعلي

المشروع Next.js 16.4.3 وReact 19 وPrisma 6.12 وPostgreSQL. كان يحتوي على هوية وجلسات، شركات ومكاتب، عضويات وأدوار، تفويضات مكتب إلى شركة، إعدادات محاسبية أولية، حسابات بنكية، مستندات، وسجل `AuditEvent`. لم يكن يحتوي دليل حسابات أو قيود أو أرصدة افتتاحية. صفحة V9 العامة بقيت كما هي.

نسخة العمل المحلية كانت تحمل تعديلات Phase 1.7/1.8 غير منشورة على schema وmigrations وAPI واختباراتها، ومنها `next-env.d.ts`. حُفظت هذه التعديلات ولم تُستبدل. **ترحيل Phase 2A المحلي مبني بعد هاتين المرحلتين المحليتين؛ لذلك لا يجوز دفعه إلى فرع الإنتاج أو تشغيله على Neon قبل مراجعة تسلسل الترحيلات كاملًا.**

## 2. نموذج النشاط التجاري

أُضيف `CompanyBusinessActivity` بالقيم `COMMERCIAL` و`INDUSTRIAL` و`SERVICE` في `CompanyAccountingSettings.businessActivity`، مستقلًا عن `OrganizationType` الذي يصف نوع الكيان وملكيته. حقل `OrganizationProfile.businessActivity` النصي القديم بقي كما هو للتوافق؛ مصدر قرار قالب الدليل الجديد هو التصنيف المنفصل وتثبيت القالب.

القالب **التجاري فقط جاهز**. يظهر الصناعي والخدمي بخططهما المنفصلة، ولا يمكن تهيئتهما عبر API أو الواجهة في Phase 2A.

## 3. نموذج البيانات والقيود

| النموذج | الغرض والحقول المهمة |
| --- | --- |
| `ChartAccount` | UUID، الشركة، الكود، الاسم العربي والإنجليزي، الأب، نوع الحساب، تصنيف القوائم، الطبيعة، المقابل، المجموعة/الترحيل، النشاط، سياسة الجرد، الأصل والإصدار، revision، المنشئ والمعدل، تواريخ الإنشاء والتعديل والحذف المنطقي. **لا يحتوي رصيدًا**. |
| `ChartInstallation` | سجل فريد لكل شركة: النشاط، إصدار القالب، عدد الحسابات، منفذ التهيئة، وتاريخ الخادم. |
| `ChartChangeRequest` | طلب تغيير حساس برقم مراجعة الحساب، الحالة، السبب، صاحب الطلب، المراجع، والقرار؛ لا يغيّر الحساب قبل الاعتماد. |
| `AuditEvent` القائم | يسجل أحداث الدليل مع رمز الحساب ولقطة اسم الفاعل والقيم السابقة والجديدة والحقول المتغيرة والسبب ومعرف الطلب وتوقيت الخادم. |

قيود PostgreSQL: `(organizationId, code)` فريد حتى بعد الحذف المنطقي؛ علاقة الأب مركبة `(parentId, organizationId) → (id, organizationId)` تمنع أبًا من شركة أخرى؛ صيغة الكود رقمية؛ منع الأب الذاتي؛ وأصل الحساب `MANUAL` أو `TEMPLATE` فقط. العلاقات مع الشركة `RESTRICT` لحماية السجل المحاسبي. لا توجد عمليات حذف جماعية للدليل.

## 4. القالب التجاري الكامل

الإصدار: `commercial-eg-1.0.0`. عدد الحسابات: **226**، منها **46 مجموعة غير قابلة للترحيل** و**180 حسابًا تفصيليًا**. التوزيع: 71 أصول، 42 التزامات، 14 حقوق ملكية، 23 إيرادات، 76 مصروفات وتكلفة مبيعات. البيانات كلها هيكلية؛ لم تُنشأ أرصدة أو قيود أو مبيعات فعلية.

| الجذر | البنية الرئيسية |
| --- | --- |
| `1000` الأصول | `1100` متداولة: نقدية وبنوك، عملاء، مخزون، سلف، مصروفات مقدمة، ضرائب مستردة، أصول أخرى. `1200` غير متداولة: ثابتة، مجمع إهلاك، غير ملموسة، وأصول أخرى. |
| `2000` الالتزامات | `2100` متداولة: موردون، دفعات عملاء، استحقاقات، عاملون، ضرائب، تمويل قصير. `2200` غير متداولة. |
| `3000` حقوق الملكية | رأس المال، الأرباح والاحتياطيات، الجاري والمسحوبات. الحسابات المرتبطة بالشكل القانوني غير معلنة كصالحة تلقائيًا؛ تبدأ غير نشطة حتى مراجعتها. |
| `4000` الإيرادات | مبيعات محلية/تصدير/جملة/تجزئة وقنوات إلكترونية؛ `4200` مردودات وخصومات كإيرادات مقابلة مدينة؛ إيرادات تشغيلية أخرى. |
| `5000` تكلفة المبيعات | `5100` للجرد المستمر، `5200` لمشتريات الجرد الدوري، `5300` لفروق وتسويات المخزون. |
| `6000` تشغيلية | بيع وتوزيع، عمومية وإدارية، إهلاك وإطفاء، عاملون. |
| `7000` تمويلية وأخرى | فوائد وخسائر عملة، مصروفات غير تشغيلية، ضريبة الدخل. |
| `8000` إيرادات غير تشغيلية | فوائد وأرباح عملة وبيع أصول. بقيت مصنفة إيرادات لا مصروفات. |

أمثلة مهمة: `112006` مخصص خسائر ائتمان دائن مقابل للأصول؛ `122001` مجمع إهلاك دائن مقابل؛ `116001` ضريبة مدخلات قابلة للخصم منفصلة عن `215001` ضريبة مخرجات؛ `420001` مردودات مبيعات مدينة مقابلة للإيراد؛ `810001` إيراد فوائد دائن. لا توجد نسبة ضريبة مفترضة ولا رصيد بنك مختلق ولا حساب أستاذ مستقل إجباري لكل عميل أو مورد.

سياسة الجرد تحدد تنشيط فرع `5100` أو `5200` عند التهيئة. الفرع غير الملائم يبقى موجودًا ولكنه غير نشط. تغيير السياسة بعد التهيئة يُرفض حتى توجد إجراءات ترحيل ومراجعة مستقلة؛ لا يوجد محرك مخزون أو ترحيل مشتريات في هذه المرحلة. لا تُكرر رواتب العملية تلقائيًا بين المجموعات، لأن محرك الترحيل لم يُنفذ.

## 5. التهيئة الآلية والنسخ

عند اختيار «النشاط التجاري» من شاشة الإعداد، تتحقق API من الجلسة وصلاحية `accounting:chart:template:initialize` ونوع الشركة. تدخل العملية معاملة `Serializable`، وتقفل صف الشركة، وتتحقق من عدم وجود دليل أو تركيب سابق. تُنشئ الحسابات بربط UUIDات الأبناء بالآباء، وتضبط النشاط في الإعدادات، وتكتب `ChartInstallation` وثلاثة أحداث تدقيق، ثم تُثبت الجميع معًا. لا تظهر رسالة النجاح إلا بعد الرد الناجح من الخادم.

الاستدعاء المكرر يعيد الدليل الموجود دون إنشاء حسابات جديدة، ولا يمحو حسابًا يدويًا أو يبدّل إصدار قالب سبق تثبيته. اختيار نشاط آخر أو وجود دليل سابق بلا تثبيت يرجع رفضًا واضحًا. التزامن محمي بقفل الشركة وقيد التفرد؛ قد يُطلب من أحد الطلبين المتوازيين إعادة المحاولة عند تضارب Serializable، لكن لا تنشأ نسختان.

لا يوجد في Phase 2A ترقية تلقائية لقالب منشور على شركة قائمة. تحتاج الترقية المستقبلية تحليل فروق وتأثير واعتمادًا مستقلًا.

## 6. الأكواد والشجرة

تستخدم المجموعات الأساسية رموزًا رباعية، وتستعمل الحسابات التفصيلية رمز الأب زائد خانتين؛ الحسابات الجديدة تقترح أصغر خانتين متاحتين في فرعها. يسمح بتعديل الكود يدويًا مع احترام صيغة الشركة والفرع، ويمنع قيد قاعدة البيانات تكراره عند التزامن. لا يُعاد استخدام رمز حساب محذوف منطقيًا. إعادة ترقيم أو نقل حساب قالب ممنوعة وتحتاج ترحيلًا محاسبيًا مستقلًا.

الأب لا يقبل الترحيل، والحساب التفصيلي لا يقبل أبناء. تتأكد الخدمة من شركة الأب ونشاطه وصلاحيته، وتحظر الدورة ونقل مجموعة ذات أبناء أو تحويلها إلى حساب قابل للترحيل. التصنيف في القوائم يجب أن يطابق نوع الحساب، وطبيعة الحساب المقابل تُراجع. لا توجد عملية تعديل مباشر لرصيد الحساب.

## 8. سجل التدقيق والتحكم في التغييرات

الأحداث المنفذة: اختيار القالب، تطبيق إصداره، تهيئة الدليل، إنشاء حساب أو مجموعة، تعديل وصف أو اسم، تقديم طلب حساس، اعتماده أو رفضه، تعديل حساس، تعطيل، حذف منطقي، ورفض طلب حذف غير جائز. تغيير صلاحيات العضوية المحاسبية يُسجل أيضًا.

الحساب والتدقيق يُحفظان في المعاملة نفسها. التاريخ يأتي من الخادم/قاعدة البيانات ويُعرض بتوقيت `Africa/Cairo` مع وسم القاهرة. سجل المستخدم داخل API قابل للقراءة والبحث بالكود والحدث والفاعل والتاريخ والتصنيف وحالة الاعتماد؛ لا يوجد API عادي لتعديل أو حذف حدث. **جدول `AuditEvent` ليس سجلًا غير قابل للتغيير على مستوى مدير قاعدة البيانات ولا يملك توقيعًا تشفيريًا**؛ هذه فجوة تتطلب سياسة أذونات DB/حفظ مستقل عند الانتقال لمحاسبة مالية منتجة.

تغييرات الاسم والوصف ذات سبب واضح تُطبق مباشرة لمصرح له مع التدقيق. تغيير الكود أو الأب أو النوع أو تصنيف القوائم أو الطبيعة أو قابلية الترحيل أو الحالة، وكذلك الحذف، يدخل طلبًا `PENDING`. يُراجع على الخادم قبل التسجيل وعند الاعتماد مرة ثانية، ولا يُطبّق إلا بواسطة مستخدم آخر يحمل صلاحية الاعتماد، وبشرط ثبات `revision`. الرفض يسجل القرار دون تغيير الحساب. صاحب الطلب لا يعتمد طلبه. إذا لم يوجد معتمد ثانٍ، يبقى الطلب معلقًا؛ لا تتجاوز المنصة الفصل بين الواجبات.

الحذف المسموح هو **حذف منطقي فقط** لحساب يدوي بلا أبناء وبطلب معتمد. حسابات القالب لا تُحذف، ورفض محاولة حذفها يُسجل. لا توجد قيود أو دفتر أستاذ حتى الآن؛ عند إضافة محرك الترحيل يجب ربط حسابات القيود بمفاتيح أجنبية ومنع تعطيل/حذف أي حساب مستخدم قبل توسيع هذا المسار.

## 9. المسارات والواجهة

| المسار | الوظيفة |
| --- | --- |
| `/company/[id]/accounting/chart-of-accounts` | شاشة عربية RTL محمية: اختيار النشاط، شجرة قابلة للطي، بحث عربي/إنجليزي/كود، مرشحات، التفاصيل والمسار الكامل، إنشاء وتعديل، طلبات حساسة، سجل، وصلاحيات الفريق. |
| `GET/POST /api/organizations/[id]/chart` | جلب دليل الشركة وتهيئة القالب التجاري مرة واحدة. |
| `GET/POST /api/organizations/[id]/chart/accounts` | اقتراح كود وإضافة حساب أو مجموعة. |
| `PATCH /api/organizations/[id]/chart/accounts/[accountId]` | تعديل الاسم والوصف فقط مع السبب والتدقيق. |
| `GET/POST /api/organizations/[id]/chart/changes` | عرض وتقديم طلبات التغيير الحساس. |
| `PATCH /api/organizations/[id]/chart/changes/[changeId]` | اعتماد أو رفض بواسطة شخص آخر. |
| `GET /api/organizations/[id]/chart/audit` | سجل تدقيق الشركة بمرشحات. |
| مسارات العضوية والتفويض القائمة | توسيع مضبوط لمنح صلاحيات الدليل ضمن حدود المانح والتفويض والدور. |

تظهر وصلة الدليل من ملف الشركة والقائمة الجانبية، ومن ملف المكتب فقط إذا ثبتت صلاحية الموظف في الشركة المفوضة. للموبايل قائمة مختصرة خاصة بهذه الشاشة. الحالات الصناعية والخدمية موضحة بصدق على أنها غير جاهزة، وأرقام الحسابات **ليست أرصدة**. الأزرار الحساسة لا تظهر إلا حسب الإذن ثم تُعاد حمايتها خادميًا.

1. **عائق نشر حرج:** `prisma/schema.prisma` وmigrations Phase 1.7/1.8 معدلة محليًا مسبقًا وغير موجودة في فرع الإنتاج. دفع Phase 2A الآن قد يبني Prisma Client يتوقع أعمدة لم تُنشأ على Neon، فيعطل حتى صفحات شركة قائمة. لا توجد موافقة مستقلة لترحيل قاعدة Production أو نتيجة rehearsal على نسخة آمنة من بياناتها.
2. جدول التدقيق لا يحمل ضمان عدم التغيير على مستوى DBA؛ توجد حماية على مستوى API والمعاملات فقط.
3. لا توجد قيود/أرصدة/دفتر أستاذ أو روابط استخدام مالية بعد؛ عند إضافتها يلزم منع تعديل أو حذف الحساب المستخدم بمراجع فعلية، واختبار ترحيل بيانات موجودة.
4. لم يُربط حساب الأستاذ بعد بسجل `CompanyBankAccount`، ولا يوجد دفتر فرعي للعملاء أو الموردين. البنية تسمح بالربط لاحقًا دون اختلاق أرصدة.
5. لم تُنفذ ترقية قالب شركة موجودة ولا تحويل نشاطها ولا محرك جرد أو ضرائب أو توزيع قيود؛ التغيير يحتاج مسارًا مستقلًا بمراجعة أثر.
6. مسار الاعتماد يتطلب شخصًا ثانيًا. لا يوجد بديل ذاتي للمالك المنفرد؛ تبقى طلباته الحساسة معلقة حتى تعيين معتمد مناسب.
7. الفحص البصري والبناء اختُبرا في معاينة معزولة؛ لم يُنفذ E2E على قاعدة Production أو جلسة عميل حقيقي، ولم يُقَس Lighthouse. مرشح التاريخ في سجل التدقيق يستخدم حدود يوم UTC بينما العرض موسوم بتوقيت القاهرة؛ يلزم توحيد حدود البحث المحلية قبل الاعتماد التنظيمي النهائي.
8. حدث تشغيل أولي لـPrisma CLI أبلغ أنه حمّل ملف `.env` تلقائيًا أثناء التحقق من schema؛ لم تُعرض أو تُنسخ أي قيمة، وجميع اختبارات الترحيل والبناء اللاحقة أجريت في بيئات منسوخة ومعزولة بمتغيرات اختبار. لم تتصل أي أداة بـNeon.

## 14. خطة النشاط الصناعي

قالب مستقل وإصدار منفصل يبدأ بمواد خام، إنتاج تحت التشغيل، منتج تام، تكاليف عمالة مباشرة وغير مباشرة، تحميل التكاليف الصناعية، أوامر إنتاج، مراكز تكلفة، فروق إنتاج وهالك، وتكلفة مبيعات صناعية. تُحدد سياسة التكاليف وعلاقة GL بالمخزن والإنتاج قبل إنشاء الحسابات، مع اختبار عدم معاملة WIP كمصروف أو اعتبار كل إنتاج مباعًا. يبقى `INDUSTRIAL` غير قابل للتهيئة الآن.

## 15. خطة النشاط الخدمي

قالب مستقل وإصدار منفصل يضم إيرادات خدمات ومشروعات وعقود، إيرادات مؤجلة وغير مفوترة وفق السياسة، عمالة مباشرة، تكاليف مشروعات، مقاولي باطن، WIP للمشروعات المؤهلة، وتكلفة الخدمات. تُراجع قواعد الاعتراف بالإيراد والقطاعات الفرعية قبل التشغيل. يبقى `SERVICE` غير قابل للتهيئة الآن.

## 16. جاهزية Phase 2B — أرصدة أول المدة

الدليل يوفر معرّفات ثابتة، أنواعًا وطبيعة ومجموعات تقارير وحسابات قابلة للترحيل، وهي أساس مناسب لـPhase 2B. لا يحتوي الرصيد داخل الحساب. المرحلة التالية تحتاج إدخالًا يدويًا واستيراد Excel إلى staging، مبالغ Decimal، فحص توازن المدين والدائن، مراجعة بشرية واعتمادًا وقفل نسخة وسجل تدقيق، ثم الربط بمحرك قيود مزدوجة. لا يجوز إنتاج رصيد تجريبي على حسابات شركة حقيقية.

## 17. قرار النشر وخطوات الاعتماد

**لم يُنشأ Commit، ولم يحدث Push أو Deploy، ولم تُنفذ migration على Neon أو أي قاعدة مشتركة.** طلب النشر في الرسالة المباشرة يتعارض مع شرط الأمان المحدد في قسم 26 من مواصفات Phase 2A: عدم commit/push قبل مراجعة التنفيذ واعتماد سلامة ترحيل قاعدة Production بصورة منفصلة، وعدم نشر تغييرات schema على Production. كذلك التسلسل المحلي الحالي يعتمد على migrations سابقة غير منشورة. لذلك بقيت الشفرة والتقرير محليين وقابلين للمراجعة، ولم يُنشر نظام يعتمد على جداول غير موجودة.
