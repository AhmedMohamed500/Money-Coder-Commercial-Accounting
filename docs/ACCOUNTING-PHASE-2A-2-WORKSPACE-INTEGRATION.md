# Money Coder — تقرير دمج مساحة عمل الشركة المحاسبية Phase 2A.2

**التاريخ:** 1 نوفمبر 2026، توقيت القاهرة
**الحالة:** تنفيذ محلي مكتمل ومختبر؛ **جاهز لمراجعة سلامة النشر فقط**.
**النطاق:** منطقة الشركة بعد تسجيل الدخول. صفحة V9 العامة والهوية ونظام المستندات لم تُغيَّر في هذه المرحلة.

## 1. الملخص التنفيذي

أصبح دخول `/company/[id]` يفتح **لوحة تشغيل الشركة** بدل معالج البيانات ذي الخطوات الست. نُقل المعالج نفسه إلى `/company/[id]/settings` مع بياناته وواجهات API وصلاحياته القائمة. أُدمج دليل الحسابات التجاري Phase 2A في قائمة شركة موحدة، مع روابط فعلية للدليل، سجل تعديلاته، إعدادات الشركة، والفريق عند وجود الصلاحية. الوحدات المحاسبية التالية معروضة كمراحل غير متاحة، دون أرقام مالية أو مسارات وهمية.

اللوحة تقرأ سجلات الشركة الحالية فقط. لا تُنشئ دليلًا أثناء فتح الصفحة. اختبار المعاينة أنشأ الدليل **صراحةً** بعد تأكيد المستخدم على قاعدة PostgreSQL مؤقتة، وأثبت وجود **226 حسابًا**. لم يُنفذ Commit أو Push أو Deploy أو أي ترحيل على Neon أو قاعدة مشتركة.

## 2. مشكلة التنقل السابقة

كان المسار الأساسي للشركة يعرض نموذج التسجيل وحده، فكانت الحسابات والإعدادات التشغيلية مبعثرة ولا توجد نقطة دخول واضحة إلى دليل الحسابات. لم يكن هناك فصل بصري بين الوحدات الجاهزة وما زال مخططًا لها. عالجنا ذلك بلوحة شركة مستقلة وقائمة جانبية مشتركة، مع إبقاء نموذج التسجيل كاملًا في الإعدادات.

## 3. بنية لوحة الشركة الجديدة

- المسار: `/company/[id]`، صفحة خادمية تتطلب جلسة مستخدم وصلاحية `organization:view` لهذه الشركة.
- `loadCompanyContext` يتحقق من نوع الكيان، عدم حذفه، وحقوق الدليل والتدقيق والفريق والتهيئة بواسطة `authorizeOrganization`.
- `loadCompanyOperations` يجلب التصنيف المحاسبي المعتمد، السنة المالية، عدد الحسابات البنكية المسجلة، عدد أعضاء الشركة المسموح بعرضه، سجل تثبيت الدليل، وعدد الحسابات الفعلي لهذه الشركة. قراءة التثبيت والحسابات مشروطة بصلاحية الدليل.
- الواجهة تعرض اسم الشركة، حالة ملفها، النشاط، السنة المالية، بيانات البنوك **كعدد سجلات فقط**، الفريق، إصدار القالب وسياسة الجرد عند وجود تثبيت، والإجراءات السريعة.
- لم تُضف أرصدة بنكية أو مؤشرات مبيعات أو ربح أو مصروفات. الحساب البنكي المسجل لا يعني اتصالًا بالبنك.

## 4. القائمة الجانبية والتصميم

المكوّن `CompanyShell` يخدم لوحة الشركة والإعدادات والدليل. يعرض اسم الشركة، حالة الوصول عبر مكتب مفوض، رابط الرئيسية، دليل الحسابات، سجل تعديلاته بحسب إذن التدقيق، إعدادات الشركة، ورابط الفريق والصلاحيات عند وجود حق الإدارة. يوجد قسم قابل للطي للمراحل القادمة يذكر الأرصدة الافتتاحية والقيود والأستاذ والميزان والقوائم والإقفال، **بعناصر معطلة وليست روابط**. الألوان من لوحة Money Coder: الكحلي `#102B4C`، التركوازي الداكن `#064B50`، الأبيض وخلفية فاتحة.

على الموبايل يوجد درج بقائمة وزر واضح؛ يُغلق عند اختيار رابط أو ضغط Escape، مع حالة `aria-expanded` وعناصر تركيز. اختُبر عدم وجود تمرير أفقي في ستة عروض. حالة الرابط النشط تتغير بين اللوحة والدليل وسجل التدقيق والإعدادات.

## 5. دمج دليل الحسابات

أُعيد استخدام شجرة ودوال وخدمات وواجهات API الخاصة بـPhase 2A، دون إنشاء نسخة ثانية منها. رابط الدليل من اللوحة والقائمة يفتح `/company/[id]/accounting/chart-of-accounts`. الرابط `?view=audit` يفتح لوحة السجل مع فحص صلاحية التدقيق على الخادم، و`#team-access` يصل إلى صلاحيات الفريق إن كان المستخدم مخولًا.

إذا لم يوجد تثبيت، تُعرض خطوة اختيار النشاط التجاري وتهيئته لصاحب الحق فقط. **زيارة الصفحة أو اللوحة لا تستدعي التهيئة**. النقر على «إنشاء الدليل التجاري» يتطلب تأكيدًا واضحًا، ثم يستعمل API وخدمة Phase 2A القائمة. التهيئة تعمل داخل معاملة، وتعيد التثبيت الموجود دون إعادة إنشاء حساباته. إضافة إلى منع الواجهة للتصنيف الصناعي أو الخدمي، ترفض الخدمة الآن على الخادم تهيئة قالب تجاري إذا كان `CompanyAccountingSettings.businessActivity` مختلفًا، برمز 409. الوصف النصي للنشاط في ملف الشركة ليس مصدر قرار القالب.

بقيت صلاحيات الإنشاء والتعديل والطلبات الحساسة والاعتماد والتدقيق وعزل الشركات كما في Phase 2A. عُدلت حدود فلترة تاريخ السجل إلى بداية اليوم المحلي بالقاهرة ونهاية اليوم التالي الحصرية؛ أُضيف اختبار ليوم بدء التوقيت الصيفي وانتهائه.

## 6. نقل إعدادات الشركة

المسار الجديد `/company/[id]/settings` يعرض مكوّن `CompanyWorkspace` نفسه، وبنفس استعلامات Prisma وواجهات API وسياسات الصلاحيات والتخزين. بقيت الأقسام الستة:

1. البيانات الأساسية.
2. القانونية والضريبية.
3. العنوان والتواصل.
4. الإعداد المحاسبي.
5. الحسابات البنكية.
6. المراجعة والمستندات.

يوجد رابط للرجوع إلى اللوحة، ودعم `?step=4` للوصول المباشر للبنوك، وتخطيط شبكي لعلامات الأقسام على الموبايل. عند إدخال تغيير في نموذج، يظهر تأكيد قبل تبديل القسم أو مغادرة الصفحة عبر رابط أو إغلاق الصفحة؛ رفض التأكيد يبقي البيانات المعروضة. الحفظ الناجح يعيد الحالة إلى غير معدلة. لم يُفعَّل رفع مستندات جديدة؛ تعرض الصفحة سياسة وضع الرفع وحالة التخزين كما كانت، مع التحكّم الخادمي القائم.

## 7. بيانات الشركة المحفوظة

لم يُنفذ ترحيل بيانات أو تغيير schema في Phase 2A.2. صفحة الإعدادات تقرأ `Organization` وعلاقات الملف القانوني والعناوين والاتصالات والإعدادات المحاسبية والسنوات المالية والحسابات البنكية والمستندات والتفويضات، مع شروط الحذف القائمة. اختُبرت المعاينة بحساب بنكي وسنة مالية واسم شركة محفوظين في قاعدة مؤقتة، وظهر كل منها في اللوحة والإعدادات. اختبارات التكامل القائمة تتحقق من حفظ بيانات الشركة ومنع قراءة شركة أخرى. لم يُعد اختبار إرسال كل نموذج من الأقسام الستة عبر المتصفح على حدة؛ لذلك لا يُعد ذلك إثباتًا مستقلًا لكل مسار حفظ.

## 8. الأدوار والصلاحيات

كل صفحة شركة تبدأ بالتحقق الخادمي، وكل API للدليل يواصل فحص الصلاحية الخاصة بالعملية والشركة. إخفاء رابط الدليل لا يمنح حق الوصول إلى API. حقوق الفريق والتدقيق والتهيئة منفصلة عن `organization:view`. اختبارات التكامل تغطي المالك، المحاسب بصلاحية صريحة، المشاهد، رفض مستخدم شركة أخرى، منع تصعيد الصلاحيات عبر المدير أو المانح، وتعليق العضوية. لا توجد جولة متصفح مستقلة لكل دور؛ اعتمدت تغطية الواجهة المرئية على مستخدم تجريبي مالك وموظف مكتب.

## 9. تفويض مكتب المحاسبة

يُستعمل `authorizeOrganization` القائم لتقاطع عضوية المكتب والتفويض النشط وتعيين الموظف وصلاحياته. يظهر «وصول عبر تفويض مكتب محاسبة» في سياق الشركة للمستخدم المفوض. اختُبرت زيارة موظف مكتب مخول بصريًا، ثم أُلغي التفويض داخل قاعدة الاختبار وأعاد المسار 404. اختبارات التكامل تغطي كذلك العضو المعلّق والتفويض المسحوب. لا يحصل المكتب تلقائيًا على صلاحيات حسابات جميع الشركات.

## 15. العوائق والحدود المتبقية

1. **عائق نشر حرج:** تسلسل migrations المحلي يتضمن تغييرات أمنية ومحاسبية لم تُطابق بعد مع قاعدة Production؛ حالة drift وترحيلات Neon غير مثبتة. التطبيق المنشور لا يُفترض أنه يملك `ChartAccount` أو أعمدة الفحص ومحددات الصلاحية.
2. لم تُنفذ أرصدة أول مدة أو قيود أو أستاذ أو ميزان أو قوائم أو إقفال. عرضها مرحلي ومعطل عمدًا.
3. القالب الصناعي والخدمي غير جاهزين. لا يُستخدم القالب التجاري لهما.
4. التهيئة تتطلب حقًا صريحًا، والتغييرات الحساسة لا تزال تتطلب مُعتمدًا ثانيًا؛ المالك المنفرد قد تبقى طلباته معلقة وفق نموذج فصل الواجبات الحالي.
5. اختبار المتصفح استخدم مستخدمًا تجريبيًا وقاعدة مؤقتة. لم يغطِّ حفظ كل نموذج من الخطوات الست أو كل دور في المتصفح، ولم يُختبر على بيانات إنتاج حقيقية.
6. AV/quarantine والتكوين الخارجي للتخزين من العمل الأمني السابق لم يُستكملا هنا؛ وضع الرفع في المعاينة معطل، ولا يُستنتج من هذه المرحلة أن رفع المستندات أصبح جاهزًا للعامة.
7. سجل التدقيق محفوظ وفق صلاحيات ومعاملات التطبيق؛ لم يُثبت أنه غير قابل للتغيير على مستوى مسؤول قاعدة البيانات.

## 16. متطلبات النشر الدقيقة، في مهمة مستقلة وبعد اعتماد صريح

1. مراجعة كل التعديلات المحلية السابقة وفصل ما يخص Phase 1.7/1.8/2A/2A.2، مع ضمان عدم فقد أي ملف أو ترحيل؛ ثم إعداد خطة إصدار موحدة وتحديد commit ونسخة Prisma Client المتوافقة.
2. فحص حالة migrations والمخطط الحقيقي في Production **بقراءة مصرّح بها فقط** ومقارنتها بالمسار المحلي؛ توثيق أي drift قبل كتابة أي شيء.
3. أخذ نسخة احتياطية قابلة للاستعادة، وتجربة الترحيلات الأربع بالترتيب على نسخة معزولة من مخطط/بيانات ممثلة، وفحص سجلات الشركات والمستندات والتفويضات الحالية بعد كل خطوة. معالجة الانحراف بخطة خاصة؛ لا تشغيل عشوائي لـ`migrate deploy`.
4. مراجعة `PRIVATE_STORAGE_UPLOAD_MODE` والإعدادات الأمنية؛ إبقاء الرفع مغلقًا إلى أن تجتاز متطلبات AV والعزل والتحقق. لا ينبغي أن يؤدي نجاح الاتصال وحده إلى فتح الرفع.
5. بعد اعتماد نتائج التجربة، تطبيق ترحيلات متوافقة أولًا، والتحقق من `_prisma_migrations` والجداول والقيود وحقوق الوصول، ثم نشر التطبيق المتوافق ومراقبة الأخطاء، مع خطة رجوع للتطبيق وبياناته. لا تُنشأ أدلة شركات العملاء تلقائيًا؛ التهيئة باختيار وتأكيد وصلاحية.
6. إجراء اختبار قبول على شركة تجريبية منفصلة، وقياس الوصول عبر المالك والمحاسب والمشاهد والمكتب المفوض قبل إتاحة الميزة للجمهور.

**لم تُنفذ أي من خطوات Production السابقة في هذه المهمة.** لم يحدث Commit أو Push أو Deploy، ولم يُلمس GitHub أو Vercel أو Neon أو قاعدة خارجية.
