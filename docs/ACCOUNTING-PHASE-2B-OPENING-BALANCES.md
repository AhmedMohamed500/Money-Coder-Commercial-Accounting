# Money Coder — تقرير Phase 2B: دليل الحسابات وأرصدة أول المدة

**تاريخ التقرير:** 3 نوفمبر 2026
**النطاق:** تنفيذ وتحقق محليان فقط. لم يحدث Commit أو Push أو نشر أو اتصال بـ Neon Production أو Vercel أو GitHub.
**حالة التسليم:** الوحدة تعمل محليًا، وتحتاج مراجعة ترحيلات وتوافق وأمن قبل تفعيلها في Production.

## 1. الوضع قبل التنفيذ

- الفرع المحلي الحالي لم يكن يحتوي وحدة دليل الحسابات التي أشار إليها تقرير Phase 2A.2. وُجدت نسختها في الفرع المحلي `codex/phase-2a2-release-candidate`، فتم دمج ملفات الوحدة المطلوبة داخل مساحة العمل الحالية دون تغيير Git metadata أو المساس بالتعديلات السابقة.
- جرى التأكد من قالب النشاط التجاري الفعلي: **226 حسابًا، منها 46 مجموعة و180 حسابًا تفصيليًا**. القالب الصناعي والخدمي غير جاهزين، ولا يُستخدم القالب التجاري لهما.
- كانت صفحة الشركة تعرض خطوات تأسيس الملف. نُقلت إلى `/company/[id]/settings` مع إبقاء بياناتها وواجهتها، وأصبحت `/company/[id]` مساحة عمليات الشركة.
- لا توجد قيود يومية أو أستاذ عام حقيقيان في هذا النطاق. لا تُعرض أرصدة الافتتاح المعتمدة على أنها مُرحّلة.

## 2. ما نُفّذ

### مساحة عمليات الشركة ودليل الحسابات

- تنقل عربي RTL: لوحة الشركة، دليل الحسابات، أرصدة أول المدة، إعدادات الشركة، الفريق، مع بيان واضح بأن باقي الوحدات مراحل لاحقة.
- قراءة نشاط الشركة، السنة المالية، الحسابات البنكية المسجلة، عدد أعضاء الفريق، وحالة الدليل من بيانات الشركة الفعلية فقط.
- دليل تجاري مستقل لكل شركة مع 226 حسابًا، عرض الشجرة والتفاصيل، صلاحيات دقيقة، طلبات تغيير حساسة، وسجل تدقيق. زيارة الصفحة لا تُعيد تهيئة الدليل.
- امتداد التفويض المحاسبي لمكتب المحاسبة: يجب تلاقي صلاحية الدور وعضوية المكتب وتفويض الشركة وتعيين الموظف.

### أرصدة أول المدة

- مسودة مرتبطة بشركة وسنة مالية وتاريخ افتتاح وعملة أساسية ودقة العملة وفق `Intl.NumberFormat`.
- إدخال مدين أو دائن لكل حساب نشط قابل للترحيل؛ لا تقبل الحسابات المجمّعة أو حسابات شركة أخرى أو القيم السالبة أو وجود مدين ودائن معًا للحساب نفسه.
- حساب إجماليات المدين والدائن والفرق حسابًا عشريًا دقيقًا باستخدام `BigInt`، مع رسائل تحقق من جهة الخادم.
- دورة `DRAFT → SUBMITTED → REVIEWED → APPROVED` أو `REJECTED → DRAFT`. المراجعة حدث مستقل داخل حالة `SUBMITTED`.
- لا يراجع مُعدّ الدفعة أو مقدمها الدفعة بنفسه، ولا يبدأ الاعتماد قبل تسجيل مراجعة شخص آخر. الواجهة توفر دعوة مراجع وضبط صلاحياته من خلال مسارات العضوية الحالية، وتشرح تعليق الدفعة عند عدم وجود مراجع.
- النسخة المعتمدة مقفلة في الخدمة وداخل PostgreSQL. التصحيح ينشئ مسودة جديدة بنسخة من السطور وسبب موثق، ثم يستبدل النسخة السابقة عند اعتماد التصحيح، مع الاحتفاظ بها تاريخيًا.
- قيد فريد جزئي يضمن نسخة `APPROVED` واحدة فقط لكل شركة وسنة مالية. تعمل المراجعات `revision` وقفل صف الشركة والمعاملات التسلسلية على منع حفظ نتيجة قديمة أو تنفيذ متزامن متعارض.
- شاشة بحث وتصنيف وجدول حسابات لسطح المكتب وبطاقات إدخال واضحة للهاتف، مع تحذير من ترك تعديلات غير محفوظة.

### استيراد Excel

- تنزيل قالب XLSX للحسابات التفصيلية النشطة للشركة، وعناوين أعمدة بالعربية.
- قبول XLSX فقط حتى **2 ميجابايت، 1000 صف و20 عمودًا**. فحص بنية ZIP وحدّ المحتوى المفكوك، ورفض التشفير والصيغ والروابط والمكونات النشطة والملفات غير المدعومة.
- اكتشاف عناوين عربية/إنجليزية وربط الأعمدة يدويًا عند الحاجة، ومعاينة الصفوف وربط الأكواد غير المعروفة بحساب موجود دون إنشاء حساب تلقائيًا.
- فحص تكرار الحسابات والقيم والجانب المدين/الدائن قبل التأكيد. يمنع تكرار رفع الملف نفسه للدفعة، ويطلب تأكيدًا صريحًا قبل استبدال رصيد محفوظ داخل **المسودة فقط**.
- لا يُحفظ ملف Excel الخام في Storage. تُحفظ صفوف المعاينة في PostgreSQL ضمن الشركة والدفعة مع انتهاء صلاحية منطقي بعد 24 ساعة؛ لا يجوز تطبيق المعاينة بعد انتهائها أو بعد تطبيقها.

## 3. نموذج البيانات والترحيلات المحلية

أضيفت نماذج `OpeningBalanceBatch` و`OpeningBalanceLine` و`OpeningImportStage`، وحالات `OpeningBalanceStatus` و`OpeningImportStatus`، وعلاقات مركبة تشمل `organizationId` لعزل الشركة. يحتفظ سطر الرصيد بنسخة من كود الحساب واسمه وتصنيفه وطبيعته عند حفظه.

الترحيلات المحلية:

1. `prisma/migrations/20261031010000_phase2a_chart_of_accounts/migration.sql` — دليل الحسابات التجاري.
2. `prisma/migrations/20261102010000_phase2b_opening_balances/migration.sql` — الأرصدة، القيود، الفهارس، قفل النسخ المعتمدة.

نجح تطبيق الترحيلات الثلاثة، بما فيها الترحيل الأصلي، على قاعدة PostgreSQL **مؤقتة فقط**. لم تُنفذ أي ترحيلات على قاعدة حقيقية أو مشتركة.

## 4. المسارات والصلاحيات

| المسار | الوظيفة | صلاحية الخادم |
|---|---|---|
| `GET/POST /api/organizations/[id]/opening-balances` | العرض وإنشاء/فتح المسودة | `view` / `create` |
| `GET/PATCH /api/organizations/[id]/opening-balances/[batchId]` | التفاصيل، الفحص، التقديم، المراجعة، الرفض، الاعتماد | حسب الإجراء |
| `PUT /api/organizations/[id]/opening-balances/[batchId]/lines` | حفظ سطر حساب | `edit` |
| `GET /api/organizations/[id]/opening-balances/template` | تنزيل قالب Excel | `view` |
| `POST /api/organizations/[id]/opening-balances/[batchId]/imports` | رفع الملف ومعاينته | `import` |
| `POST /api/organizations/[id]/opening-balances/[batchId]/imports/[stageId]` | تطبيق/رفض المعاينة | `import` |
| `GET /api/organizations/[id]/opening-balances/[batchId]/audit` | أحداث الدفعة | `audit:view` |

كل مسار يتحقق من الجلسة والشركة والصلاحية على الخادم. وتُفحص ترويسة Origin لطلبات التعديل مقابل `Host` والبروتوكول الواردين، مع دعم اختلاف عنوان الخادم الداخلي خلف الوكيل ورفض الأصل الخارجي. صلاحيات الأرصدة هي `view`, `create`, `edit`, `import`, `submit`, `review`, `approve`, `audit:view` تحت بادئة `accounting:opening:`. لا يعتمد الأمان على إخفاء الأزرار.

## 5. التدقيق والمحاسبة

- الأحداث الناجحة تُكتب في المعاملة نفسها مع `organizationId` و`batchId` والمستخدم والوقت و`requestId` مولّد على الخادم والقيم السابقة والجديدة أو سبب القرار.
- تُعرض أوقات الأحداث بتوقيت `Africa/Cairo` بينما تُحفظ الطوابع الزمنية في قاعدة البيانات بصورة موحدة.
- لا توجد أرصدة مباشرة على سجلات `ChartAccount`، ولا قيد يومية أو ترحيل مصطنع.
- **عقد الترحيل المستقبلي:** تقرأ خدمة القيود نسخة `APPROVED` وقائمة سطورها الثابتة داخل معاملة، وتستخدم مفتاح تكرار فريدًا من الشركة والسنة والدفعة، وتنشئ قيد افتتاح متوازنًا واحدًا بإشارة صريحة إلى `batchId` و`revision`. لا تتغير حالة «مُرحّل» إلا بعد نجاح قيد الأستاذ الحقيقي في المعاملة نفسها. يجب رفض إعادة ترحيل النسخة نفسها أو ترحيل نسخة تاريخية `SUPERSEDED` دون سياسة تصحيح محاسبي واضحة.

3. تنتهي صلاحية معاينة Excel منطقيًا بعد 24 ساعة، لكن **لا توجد مهمة مجدولة لحذف الصفوف المنتهية** إذا لم تُنشأ عملية تنظيف مستقلة؛ يلزم تحديد سياسة احتفاظ وتنظيف قبل الاستخدام الإنتاجي الواسع.
